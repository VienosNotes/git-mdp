# フェーズ 1：表示方式の検証結果

## 実行環境

- Node.js 22（v22.22.0 で確認）、TypeScript 5.9、markdown-it 14.1
- `npm install` の後、`npm run sample` で `fixtures/` の各サンプルから `out/<名前>.html` を生成する。生成した HTML はブラウザで直接開く。
- `npm test` で、本文の復元と HTML への埋め込みを確認する。
- フィクスチャの `diff.patch` は `fixtures/make-patches.sh` で再生成する（`git diff --no-index -U3`）。

## 構成

| ファイル | 役割 |
|---|---|
| `src/diff.ts` | パッチを解析し、変更前の本文と合わせて全行の状態（変更なし・削除・追加）、変更前後の行番号、hunk との対応を作る |
| `src/render.ts` | 統合表示と更新後のみの表示の本文を markdown-it で描画し、単体 HTML を組み立てる |
| `assets/client.js` | 差分マークの配置、diff ポップアップ、表示モードの切り替え |
| `assets/style.css` | 標準 CSS |
| `src/sample.ts` | フィクスチャから検証用 HTML を生成する |

更新後の本文はファイルから読まず、変更前の本文にパッチを当てて復元する（PLAN-CLI のフェーズ 2 の方針を先取り）。

## 描画の方法

- markdown-it の core ルールで、行範囲（`token.map`）を持つブロックに `data-ls` / `data-le` を付ける。
- ブロック内の空行以外がすべて削除、またはすべて追加なら、そのブロック全体を装飾する。
- 変更が混在する段落などは、`softbreak` を数えて各テキストのソース行を求め、末端のテキストとインラインコードを行ごとに `span` で包む。強調などが行をまたいでも入れ子は壊れない。
- コードブロックは本文を行ごとに包む。表は行（`tr`）単位で装飾する。
- 「変更行を独立して表示」（既定でオン）では、リスト外の段落を、変更なし・削除・追加の連続する行ごとに別の段落へ分割する。markdown-it の解析後にトークンを分割するため、分割した行が別の構文として解釈し直されることはない。分割位置をまたぐ強調やリンクは、そこでいったん閉じて次の段落で開き直す。
- 統合表示・更新後のみの表示と、分割の有無の組み合わせ 4 通りの本文を HTML に入れておき、表示を切り替える。
- 差分マークは、hunk の最初の変更行を含む最も内側の要素の上端に置く。対応する要素がなければ直後の要素、それもなければ文末に置く。位置が重なるマークは下にずらして並べる。
- 表示モードの切り替え時と、本文の大きさが変わったとき（`ResizeObserver`）にマークを配置し直す。

## 装飾の粒度

| 構文 | 装飾 |
|---|---|
| 段落・見出し・リスト項目・引用の行 | 行単位 |
| 表 | 行単位（ヘッダー行も含む） |
| コードブロックの本文 | 行単位 |
| ブロック全体の追加・削除 | ブロック単位 |
| 空行、リンク参照定義、コードフェンスの行、表の区切り行 | 装飾なし（マークとポップアップのみ） |

## 統合表示で崩れる、または厳密に対応できない構文

いずれもマークとポップアップから元の diff を確認でき、更新後のみの表示に切り替えられる。

- 「変更行を独立して表示」をオフにした場合、段落内の変更は、削除行と追加行が一つの段落に連結されて表示される。
- 「変更行を独立して表示」では、行をまたぐ強調やリンクが分割位置で二つに分かれ、行末の強制改行は段落の区切りになる。リスト内の段落は分割しない。
- 表のヘッダー変更：削除側のヘッダー行が、表の直前の段落になる。
- コードフェンスの情報文字列の変更（` ```js ` → ` ```ts `）：追加側のフェンス行がコード本文の一行として表示される。
- リンク参照定義の変更：先に現れる削除側の定義が使われるため、統合表示のリンク先は変更前のものになる。
- 削除行と追加行をまたぐインライン構文（強調やリンクなど）は、意図しない範囲に効くことがある。

## 確認したこと

`fixtures/` の各サンプル（段落・見出し・リスト・引用、表とコード、空行と参照定義、追加のみ、削除のみ、文書全体の追加・削除、末尾改行なし、同じ段落への複数 hunk）について、Chromium で次を確認した。

- すべての hunk にマークがあり、ホバーで対応する diff が表示される。
- クリックで固定、再クリック・×・Esc で固定解除、長い diff はポップアップ内でスクロールできる。
- 更新後のみの表示で、削除だけの hunk は直後の要素、文末の削除は文末にマークが置かれる。文書全体の削除でもマークが残る。
- 同じ段落に対応する複数の hunk のマークが重ならずに並ぶ。
- 画面幅を狭めると、折り返した行の位置にマークが追従する。

## 埋め込みとエスケープ（要確認）

- 本文：markdown-it の `html: false`（既定）により、文書中の HTML タグはエスケープされる。
- diff ポップアップ：`<script type="application/json">` に JSON として埋め込み、`<` を `<` に置き換える。これで `</script>` や `<!--` を含む行でも HTML の構造が壊れない。表示時は `textContent` で設定するため、HTML として解釈されない。
- CSS と JS：現時点では本ツールの `assets/` の内容のみを埋め込む。フェーズ 4 の `--css` で利用者の CSS を埋め込む際は、`</style>` を含む場合の扱いを別途決める。
