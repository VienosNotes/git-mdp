# フェーズ 3c：複数ファイルの HTML 表示

## 使い方

```sh
npm run build
node dist/src/cli.js --output review.html
node dist/src/cli.js --cached --output review.html -- docs/
node dist/src/cli.js main...feature --output review.html -- docs/a.md docs/b.md
```

対象となるすべての文書を一つの HTML にまとめる。先頭のファイル一覧から各文書へ移動でき、各文書の見出しには変更種別と hunk 数を表示する。

## 実装したこと

- 各文書を独立した `article` にし、本文・マーク・hunk の対応をファイル番号で分離した。
- JSON に埋め込む差分もファイルごとに保持する。ポップアップの固定対象はファイル番号と hunk 番号の組で識別する。
- ポップアップには対応するファイル名を表示する。
- 統合表示・更新後のみ、および段落分割の切り替えはページ全体に適用する。
- 各ファイル内でマークを配置し、同じ位置のマークが次のファイルに重ならないよう、必要な高さを確保する。
- 内容変更のないリネームでは、変更前後のパスと「本文の変更はありません。」を表示し、本文を省略する。
- 空ファイルの追加・削除でも一覧と見出しを残す。文書全体の削除では、更新後のみの表示でも差分マークを残す。
- 対象の変更がゼロなら、従来どおり HTML を生成せず正常終了する。
- `npm run sample` で従来の単一文書サンプルに加えて、10ファイル・14 hunks の `out/multi.html` を生成できる。

## 確認結果

Node.js v24.22.1 で `npm test` を実行し、計48件が通った。

- 複数ファイルの埋め込みデータと、ファイル一覧のリンク先・本文の対応。
- ファイル名に HTML の特殊文字があっても、HTML・JSON の構造が壊れないこと。
- CLI で複数文書を一つの HTML に出力できること。
- 空ファイルの追加・削除、本文変更のないリネームも差分なしとして除外されないこと。
- Ph1〜3b の既存テスト。

Safari で `out/multi.html` を直接開き、以下を確認した。

- 一覧に全10ファイルがあり、各本文・状態表示へ移動できる。
- 各文書に合計14個のマークが表示される。
- `add-only.md` の #1 を固定した状態から `basic.md` の #1 を選んでも、正しいファイル名と内容に切り替わる。
- 更新後のみへの切り替えで、全ファイルの本文とマークが切り替わり、固定中のポップアップが閉じる。
- 文書全体の削除でもマークを選び、削除された全文をポップアップで確認できる。
- 本文変更のないリネームは、本文を出さず状態だけ表示される。
- ウインドウ幅を半分に変更し、段落分割をオフにしても、同じ段落にある二つのマークを個別に選べる。
- 画面幅を変更した後、次のファイルのマークも対応する本文付近に配置される。

## 残す事項

- ポップアップが本文に重なることや、大量ファイル・hunk での性能は計画どおり Ph5 で評価する。
- 出力先省略、一時ファイル、標準出力、CSS 指定、ブラウザ自動起動は Ph4 の対象とする。
- 統合表示に関する既知の Markdown 構文上の制限は引き続き許容し、更新後表示と元の diff で補う。
