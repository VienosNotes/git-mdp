# フェーズ 3b：変更ファイルの列挙と取得

## 実装したこと

`collectFileDiffs` で、比較対象の変更された Markdown ファイルを列挙し、各ファイルの変更種別、変更前後のパス、変更前の本文、パッチを取得する。

- 対象の拡張子は `.md`・`.markdown`（大文字小文字を区別しない）。
- リネーム前後のどちらかが対象拡張子なら取得する。Markdown から別の拡張子へ変わる場合も含む。
- リネーム検出はリポジトリ全体に対して行い、その後で変更前後いずれかのパスに一致するものを絞り込む。
- リネームの類似度は 50% とし、コピー検出は行わない。Git がリネームと判定しなかった変更は追加・削除として扱う。
- パスは NUL 区切りの一覧から取得する。パッチは同じ比較のファイル順に対応付け、件数の不一致はエラーにする。
- 内容を変更しないリネームや空ファイルの追加・削除も、hunk の有無と独立した変更として保持する。
- 変更前のパスがない追加では本文を空文字列とする。更新後の本文は従来どおりパッチから復元する。
- 初回コミット前の `--cached` は空のツリーと比較する。

## CLI の使い方と、この段階の制限

```sh
node dist/src/cli.js --output review.html
node dist/src/cli.js --cached --output review.html -- docs/
node dist/src/cli.js HEAD~3 --output review.html -- docs/a.md docs/b.md
```

- パス省略時はリポジトリ全体を対象とする。サブディレクトリからの実行でも同じ。
- 指定したパスは実行ディレクトリ基準で解釈し、ファイルまたはディレクトリ配下に一致する変更を取得する。複数指定で重複しても一度だけ取得する。
- glob は解釈しない。リネーム前後どちらの名前でも絞り込める。
- 未追跡ファイルは対象外。ただし `git add -N` で diff に現れる新規ファイルは対象とする。
- 指定パスに対象の変更がなければ、存在しないパスや Markdown 以外のパスでも「差分なし」として正常終了する。
- 対象が一件なら従来の HTML を出力する。複数件の HTML 表示は 3c に残し、この段階では明示的なエラーにする。先頭の一件だけを出力することはない。
- リネームは前後のパスをタイトルに表示する。本文変更のない場合の専用の状態表示は 3c で追加する。
- 競合中・バイナリ・未対応の変更種別が対象に含まれた場合、処理全体をエラーにする。対象外のファイルは妨げない。
- 三点比較は index の競合に影響されない。作業ツリーの比較では、対象外の競合が出力する combined diff を除外して通常パッチを取得する。

## 確認結果

Node.js v24.22.1 で `npm test` を実行し、計45件が通った。

- 全比較モードの追加・削除・リネームと本文の復元。
- 各比較モードの変更本文と、Git が出力するパッチの一致。
- 内容を変えないリネーム、本文変更を含むリネーム、拡張子をまたぐリネーム。
- ディレクトリ・複数パスの絞り込みと重複の除外。
- サブディレクトリ基準のパス変換、日本語・空白・改行・引用符を含むパス。
- Git 設定による相対パス表示、リネーム無効化などの影響を受けない取得。
- 初回コミット前の cached 比較。
- 競合・バイナリの通知と、対象外に絞った場合の取得。
- CLI のパス省略、複数対象時の明示的エラー、対象なしの正常終了。

取得処理を中心に確認した。複数文書のブラウザでの動作確認は 3c で行う。
