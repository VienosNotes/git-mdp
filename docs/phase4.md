# フェーズ 4：出力と CSS、ブラウザ起動

## 使い方

```sh
npm run build
node dist/src/cli.js                                # 一時ファイルに保存し、既定のブラウザで開く
node dist/src/cli.js --no-open                      # 一時ファイルに保存し、その絶対パスを標準出力に出す
node dist/src/cli.js --output review.html           # 指定ファイルに保存する（ブラウザは起動しない）
node dist/src/cli.js --output review.html --open    # 指定ファイルに保存し、ブラウザで開く
node dist/src/cli.js --output - > review.html       # 標準出力に HTML を出す
node dist/src/cli.js --css custom.css               # 標準 CSS の後ろに custom.css を追加する
node dist/src/cli.js --help
```

比較対象とパスの指定（`--cached`、リビジョン、`base...tip`、`--` 以降のパス）はフェーズ 3 と同じ。

## 実装したこと

- 出力先：
  - 省略時は `<OS の一時ディレクトリ>/git-md-diff-XXXXXX/review.html` に保存する。一時ファイルは削除しない。
  - `--output -` では標準出力に HTML だけを出す。ログは標準エラー出力に出す。読み取り側が先に閉じても（`| head` など）エラーを表示しない。
- ブラウザ起動：
  - 一時ファイルなら既定で開き、`--output <ファイル>` では `--open` のときだけ開く。
  - macOS は `open`、Windows は `cmd /c start`、それ以外は `xdg-open` を使う。
  - 起動コマンドが 3 秒以内に非 0 で終わるか、実行できなければ失敗とする。終了コード `1` で終わり、保存した HTML のパスを標準エラー出力に通知する。
  - 環境変数 `GIT_MD_DIFF_BROWSER` で起動コマンドを置き換えられる（テスト用。HTML のパスを一つ目の引数として渡す）。
- CSS：
  - `--css <ファイル>` の内容を、標準 CSS の後ろの別の `<style>` 要素に埋め込む。
  - 読み込めない場合は終了コード `1` で通知する。
  - `</style` を含む CSS は、埋め込んだ `<style>` 要素が途中で閉じるため、エラーとして受け付けない（大文字・小文字を区別しない）。
- 引数：
  - `--help` / `-h` で使い方を標準出力に表示する。
  - 次は引数エラー（終了コード `2`）：`--open` と `--no-open` の併用、`--output -` と `--open` の併用、`--output`・`--css` の重複指定や値の欠落。

## 確認結果

Node.js v22.22.0 で `npm test` を実行し、計57件が通った。ブラウザ起動は、渡されたパスを記録するだけのスクリプトに置き換えて確認した。

- REQUIREMENTS.md の「HTML 出力とブラウザ起動」にある各コマンド例の動作（ブラウザ起動の有無、標準出力の内容、一時ファイルが残ること）。
- `--output -` の標準出力が HTML だけで、ログが混ざらないこと。
- 指定 CSS が標準 CSS の後ろに埋め込まれ、元の CSS ファイルを移動しても生成済みの HTML に残ること。
- ブラウザ起動コマンドが失敗した場合・存在しない場合に、終了コード `1` と保存先のパスを通知すること。
- CSS を読めない場合、`</style` を含む場合、各種の引数エラー。
- 差分がない場合は、一時ファイルの作成もブラウザ起動もしないこと。

手動確認：

- Linux（作業用コンテナ）で、`--output -` をリダイレクトしたファイルと `--no-open` の一時ファイルを Chromium で開き、マークの表示と指定 CSS による背景色の上書きを確認した。
- 作業用コンテナには `xdg-open` がないため、起動失敗時の通知だけを確認した。

## 残す事項

- 実際の既定ブラウザの起動は、利用する OS（macOS を想定）で一度手動確認する。確認できた OS をここに記録する。
- Windows での起動（`cmd /c start`）は未確認。
