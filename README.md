# git md-diff

Git で管理している Markdown 文書の差分を、レンダリングした HTML で表示する CLI。文書全体を通常の Markdown として表示しつつ、Git の行単位 diff を色分けして確認できる。

大きな Markdown 文書の Pull Request をレビューするための補助ツールで、既存の diff ビューアと併用することを想定している。

`--source` を指定すると、Markdown 以外のファイル（ソースコードなど）の差分を、レンダリングせずに行番号付きの全文で表示する。

## 必要な環境

- Node.js 22 以上
- Git

## 導入

```sh
git clone <このリポジトリ>
cd git-mdp
npm ci
npm run build
npm install -g .
```

`npm install -g .` で `git-md-diff` が npm のグローバル領域に登録され、`git md-diff` として呼び出せるようになる。

### インストール先と権限

グローバル領域の場所は Node.js の導入方法で決まり、`npm prefix -g` で確認できる。インストールには、その場所に書き込める権限が必要。

| Node.js の導入方法 | グローバル領域の例 | 必要な権限 |
|---|---|---|
| Homebrew（macOS） | `/opt/homebrew`（Intel Mac は `/usr/local`） | 自分のユーザー |
| fnm・nvm・Volta などのバージョン管理ツール | ホームディレクトリの下 | 自分のユーザー |
| nodejs.org の公式インストーラー（macOS） | `/usr/local` | 多くの場合 sudo |
| Linux ディストリビューションのパッケージ | `/usr` | sudo |

置かれるのは次の二つのシンボリックリンクだけで、コードはコピーされない。

- `<グローバル領域>/bin/git-md-diff`：コマンド
- `<グローバル領域>/lib/node_modules/git-md-diff`：クローンしたディレクトリへのリンク

コマンドは、どの方法でインストールしても、実行したユーザーの権限で動く。

sudo が必要な環境では、Homebrew やバージョン管理ツールで導入した Node.js を使うか、`npm config set prefix ~/.npm-global` でグローバル領域をホームディレクトリに変える（`~/.npm-global/bin` を PATH に追加する）ことを勧める。

### 更新

クローンしたディレクトリへのリンクなので、インストールし直す必要はない。クローンしたディレクトリで次を実行する。

```sh
git pull
npm ci          # 依存が変わった場合に必要。毎回実行してよい
npm run build   # 必須。ビルド結果の dist/ はリポジトリに含まれない
```

次の場合は `npm install -g .` をやり直す。

- `package.json` のコマンド名（`bin`）が変わったとき
- バージョン管理ツールで Node.js のバージョンを切り替えたとき（グローバル領域はバージョンごとに分かれている）

### 注意

- クローンしたディレクトリを削除・移動すると、コマンドが動かなくなる。
- クローンしたディレクトリでブランチを切り替えてビルドすると、インストール済みのコマンドもその内容になる。開発もする場合は、利用用のクローンを別に用意すると安全。

### アンインストール

`npm uninstall -g git-md-diff`。クローンしたディレクトリは削除されない。

## 使い方

```sh
git md-diff                         # index と作業ツリーの差分をブラウザで開く
git md-diff --cached                # HEAD と index
git md-diff HEAD~3                  # 指定コミットと作業ツリー
git md-diff main...feature          # 共通祖先と feature（PR のレビュー向け）
git md-diff main...feature -- docs/ # 対象のパスを絞り込む
git md-diff -h                      # 使い方を表示する
```

`git md-diff --help` は Git がマニュアルページの表示として扱うため、使い方の表示には `-h` を使う。

### 比較対象

| 指定 | 比較対象 |
|---|---|
| 指定なし | index と作業ツリー |
| `--cached` | HEAD と index（初回コミット前は空のツリーと index） |
| `<リビジョン>` | 指定コミットと作業ツリー |
| `<base>...<tip>` | `base` と `tip` の共通祖先と `tip` |

- 拡張子が `.md`・`.markdown` のファイルを対象とする。未追跡のファイルは対象外（`git add -N` したファイルは対象）。
- `--` 以降にファイルやディレクトリを指定すると、対象を絞り込める。パスは実行ディレクトリ基準で、glob は解釈しない。
- 複数のファイルは一つの HTML にまとめ、ファイル一覧から各文書へ移動できる。
- 追加・削除・リネームも表示する。本文に変更のないリネームは状態だけを表示する。

### 出力

| コマンド例 | 動作 |
|---|---|
| `git md-diff` | 一時ファイルに保存し、既定のブラウザで開く |
| `git md-diff --no-open` | 一時ファイルに保存し、その絶対パスを標準出力に出す |
| `git md-diff --output review.html` | 指定ファイルに保存する。ブラウザは起動しない |
| `git md-diff --output review.html --open` | 指定ファイルに保存し、ブラウザで開く |
| `git md-diff --output -` | HTML を標準出力に出す |

- 一時ファイルは OS の一時ディレクトリの `git-md-diff-XXXXXX/review.html` に保存する。ブラウザで読み込めるよう、**コマンド終了後も削除しない**。不要になったら手動で削除する。
- 生成した HTML は単体で表示でき、ローカルサーバーやインターネット接続は不要。
- 対象となる差分がない場合は、標準エラー出力に通知し、HTML を生成しない。
- 終了コードは、成功または差分なしで `0`、引数の誤りで `2`、Git の失敗・ファイルの読み書き失敗・ブラウザの起動失敗で `1`。ブラウザを起動できなかった場合も HTML は保存されているので、通知されたパスを手動で開く。

### ソースの表示（--source）

```sh
git md-diff --source                    # Markdown 以外のファイルの差分を表示する
git md-diff --source main...feature -- src/
```

- 拡張子が `.md`・`.markdown` 以外のファイルを対象とし、Markdown のファイルは表示しない。比較対象、パスの絞り込み、出力の指定は Markdown の場合と同じ。
- 全行を等幅で表示し、各行に変更前・変更後の行番号を付ける（更新後のみの表示では変更後の行番号だけ）。行番号はコピーの対象にならない。
- 変更前または変更後が 5,000 行または 512KB を超えるファイルは、全文を表示せず、差分の前後だけを表示する。
- バイナリファイルは、エラーにせず状態だけを表示する。
- 「変更行を独立して表示」はない。シンタックスハイライトは行わない。

### CSS の指定

```sh
git md-diff --css custom.css
```

指定した CSS は標準 CSS の後ろに埋め込まれるため、色やフォントを上書きできる。CSS の内容は HTML に埋め込まれ、元のファイルは閲覧時に不要。`</style` を含む CSS は受け付けない。

主なクラス：`.md-del`（削除行）、`.md-add`（追加行）、`.mark`（差分マーク）、`#popup`（diff ポップアップ）。色は `:root` の `--del-bg`・`--add-bg` などの変数でも変えられる。

## 画面の見方

- **本文**：削除行を赤、追加行を緑で表示する。
- **差分マーク**：本文の左の番号付きマークが、差分のまとまり（hunk）ごとに対応する。
- **diff ポップアップ**：マークにカーソルを当てると、元のソースの diff を変更前・変更後の行番号付きで表示する。クリックで固定し、再度のクリック、×、Esc で閉じる。
- **ファイル一覧**：広い画面では本文の左に、狭い画面では本文の上に表示する。いま表示している位置のファイルを強調する。
- **ツールバーのファイル名**：いま表示している位置のファイル名と変更種別を表示する。
- **ファイルの折りたたみ**：各ファイルの見出しの ▼ / ▶ で本文を折りたたむ・展開する。折りたたんだファイルは「前の hunk / 次の hunk」の移動先から外れる。削除されたファイルは折りたたんだ状態で表示する。
- **前の hunk / 次の hunk**：前後の差分マークがツールバーのすぐ下に来るようにスクロールし、対応する本文を一時的に枠で囲む。ファイルをまたいで移動できる。
- **表示: 統合表示 / 更新後のみ**：削除行と追加行を一本の文書として表示するか、更新後の本文だけを表示するかを切り替える。統合表示が崩れて読みにくい場合は「更新後のみ」に切り替える。
- **変更行を独立して表示**：段落の中で変更された行を、別の段落に分けて表示する（既定はオン）。

## 既知の制限

本文の表示が崩れても、差分マークと diff ポップアップから元の diff を確認できる。

- 統合表示では、削除行と追加行を連結して描画するため、次の変更で表示が崩れる。
  - 表のヘッダーの変更：削除側のヘッダー行が、表の直前の段落になる。
  - コードフェンスの言語指定などの変更：追加側のフェンス行がコードの本文として表示される。
  - リンク参照定義の変更：変更前のリンク先が使われる。
- 「変更行を独立して表示」では、分割位置をまたぐ強調やリンクが二つに分かれる。リスト内の段落は分割しない。
- 空行、リンク参照定義、コードフェンスの行など、本文に現れない箇所の変更は色分けされず、差分マークとポップアップだけで確認する。
- 文書中の HTML タグは描画せず、文字として表示する。
- 画像や相対リンクは、生成した HTML の場所を基準に解決されるため、表示されない・開けないことがある。
- 文字コードは UTF-8 のみ対応。
- 競合中のファイルが対象に含まれる場合はエラーになる。Markdown の表示では、バイナリファイルが対象に含まれる場合もエラーになる（`--source` では状態だけを表示する）。

## 開発

```sh
npm ci
npm test           # ビルドして全テストを実行
npm run sample     # fixtures/ から out/*.html を生成する
npm run build:web  # GitBucket プラグイン用のブラウザ用 JS（dist/web/md-diff.js）を生成する
```

各フェーズの実装記録は [docs/](docs/) に、計画は [PLAN-CLI.md](PLAN-CLI.md) に、要件は [REQUIREMENTS.md](REQUIREMENTS.md) にある。ブラウザ用 JS のデータ形式は [docs/web.md](docs/web.md) を参照。GitBucket プラグインは [gitbucket-mdp-plugin](https://github.com/VienosNotes/gitbucket-mdp-plugin) にある（計画もそちらの PLAN-GITBUCKET.md）。
